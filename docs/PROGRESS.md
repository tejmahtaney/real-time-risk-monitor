## Open issues

- Part 19: the split detector (Part 7) only sees splits inside the 100-day fetched window and only matches ratios within 2 % of 1.5, 2, 3, 4, 5, 10, 20 or their inverses. A real one-day drop of about 33 % would be misread as a 3-for-2 split. It is logged as a warning, so it is visible.
- Part 19: the simulator has one drift μ for every symbol, and the vol shocks of different symbols correlate through the price shocks (corr of W_i, W_j is ρ² times the price correlation). Neither is calibrated from data.
- Part 19: exchange holidays are ignored by `SimClock`, so a simulated session runs on days the real market is shut.
- Part 22: only backtest folders can be deleted so far (`DELETE /api/backtests/{id}/files`, confined by `storage::remove_dir_confined`, which needs the run id typed back as confirmation). Sessions, market-data files and portfolio versions still have no delete; the storage browser will need one behind an explicit user-triggered action, and can reuse that helper.
- `MarketState::rate` has no mutation path anywhere in this codebase (`MarketState::update`, called by every simulated tick, explicitly keeps it fixed). `PnlAttributor`'s rho bucket is therefore always zero. If a later part makes the rate move (a stretch item, not on the roadmap today), `PnlAttributor::on_tick`'s signature will need a rate before/after to compute a real dr.
- Part 14: the generated TypeScript bindings render every Rust `u64` (`seq`, `compute_micros`, alert `id`, …) as `number` (`TS_RS_LARGE_INT=number` in `make types`, overriding ts-rs's `bigint` default), matching how `serde_json` actually encodes a `u64` on the wire. `number` loses precision above 2^53; in practice a tick `seq` or a `compute_micros` figure never gets remotely close to that, so this is a theoretical gap, not a real one, but it is worth knowing about if `seq` is ever repurposed as a long-lived global counter.
- Part 16: the Greeks-over-time charts' warning band needs `config/limits.toml`'s `warning_threshold` (a single fraction applied to every limit), which `LimitStatus` does not carry on the wire. `frontend/src/lib/chartLimits.ts`'s `LIMIT_WARNING_THRESHOLD` duplicates the current value (`0.8`) as a documented constant instead. If `config/limits.toml`'s `warning_threshold` ever changes, this constant needs updating with it; a later part touching the backend could close this by adding the fraction to `LimitStatus` itself.
- Part 16: `frontend/scripts/screenshot.ts` has been run twice (outside this sandbox, no browser available here — same limitation as Parts 14 and 15). The first round found five layout problems; a second round confirmed four of the five fixed but found the first attempt at the chart y-axis fix (item 4) still flattened the chart for a different reason, now corrected — see `docs/notes/part-16-charts.md`'s "Screenshot review fixes". The corrected chart fix has not itself been re-screenshotted to confirm, since the no-browser limitation still applies here.
- Part 19: adjusted strikes are not rounded to a listed increment, as the OCC does (a 3-for-2 on a 240 strike gives 160 here, and 200 gives 133.33). The exact ratio is kept so value is invariant to 1e-9.
- Part 19: the escrowed dividend model applies vol only to S*, which understates long-dated options on stocks with large dividends. The Haug-Haug-Lewis, Bos-Vandermark and Beneder-Vorst models fix it and are not built.
- Part 19: on a restart the ledger is replayed into the seed's calibrated spot, so a replayed dividend is subtracted from the seed price and not from the price the simulated path had reached when it went ex. Ledger records go through the recorder's non-blocking channel and could be dropped if it were full (`dropped_records` would show it).
- Part 19: Alpha Vantage `SPLITS` returns historical splits only, so real upcoming splits cannot be loaded. Only `DIVIDENDS` (which does return declared future dividends) has a loader, and it is off by default. The `SPLITS` JSON shape was not seen live: the one request made got the 1-request-per-second burst-limit reply.
- Part 20: a replay step is a whole day, so the P&L residual is larger than in live mode, where a step is about 30 seconds. The Taylor expansion is taken over a day, so the third-order and cross terms, the gamma of a large move and the vol change all land in one step. In the real run the sum of |residual| is 7.6 % of the sum of |actual| and the median day's residual is 4.7 % of that day's P&L; the mean ratio (5.7) is dominated by days with almost no P&L, so do not read it. It is expected, and the bucket totals should be read next to the residual.
- Part 20: the Kupiec test has almost no power on a short replay. At 99 % the archive gives about 80 dates and 0.8 expected exceptions; with n = 80 the test rejects only from 4 exceptions, and a model whose true exception rate is 3 % (three times too high) is caught only 22 % of the time. A rejection is meaningful, a pass is not evidence. Upload a longer file (a few years of closes) for a real back-test.
- Part 20: replayed inputs are closes only. Vol is the 20-day realised vol (no implied vol history), so vega P&L is realised-vol change, and the VaR window is at most `vol_window_days` (60) returns, with sticky-vol full revaluation for the historical method. The Part 19 split-detector caveat applies to uploads too: a genuine one-day fall of about 33 % is read as a 3-for-2 split and back-adjusted, with a logged warning.
- Part 20: the live `config/limits.toml` was tuned for the simulated sample book, so on real history it is in breach on most days (58 of 80 in the real run). `days_with_breaches` is correct but says more about the limits than the book.
- Part 20: in a replay `snapshot.paused` is always false and `change_since_open` is 0 (a step is a whole session), and the engine's own close and `daily-pnl` records are not produced (the runner builds `daily.csv` from each snapshot). Part 21 should take play state from `GET /api/backtests/{id}`. A run cut short (stopped, freed as idle or the server restarted) is listed as unfinished and cannot be resumed.

A plain h = 1e-4 second difference fails 1e-5 relative error at 5 % vol six deviations out of the money, where the h² truncation term alone is about 6e-5. The analytic value was right.

### Part 04 - Implied volatility solver

- Built: `pricing::implied_volatility` taking an `IvRequest` and returning an `IvSolution` (volatility and iteration count) or an `IvError` (`Expired`, `BelowIntrinsic`, `AboveUpperBound`, `NoConvergence`, `InvalidInput`). Safeguarded Newton on vega with a bracket [1e-6, 10] tightened on every evaluation, bisection when vega is under 1e-12 or the step leaves the bracket, and Brenner-Subrahmanyam as the start guess. Validation reuses `BsInputs::new` with a placeholder σ of 1, and a non-finite price is `PricingError::NonFinite`. One `greeks()` call per iteration gives price and vega.
- New dependencies: none. A second criterion bench, `benches/implied_vol.rs`.
- Tests: 67 in the workspace (51 unit and property tests, 16 doc tests). 13 new unit and property tests, 1 new doc test. Every `IvError` variant has a test. The property tests also passed at 300,000 cases per test.
- Iterations: over a grid of 5,040 round-trip cases the mean is 8.64 and the maximum 33. Pure bisection needs about 50. The 64 limit holds over 300,000 random cases.
- Benchmark (release, this machine): 160 ns for one near-the-money solve and 762 ns for a deep out-of-the-money one.
- Choices the prompt left open. (1) The upper-bound tolerance is one-sided the same way as the lower: a price within 1e-12 × max(S, K) of S·e^(−qT) or K·e^(−rT) counts as on the bound and is `AboveUpperBound`. (2) A root below 1e-6, such as a price exactly on intrinsic, returns 1e-6 and not an error. (3) A root above 10 is `NoConvergence`, detected when the bracket collapses onto the ceiling with the price still out of reach. (4) Where vega is tiny the solver returns any σ that reproduces the price to 1e-12 × max(1, price), which need not be the σ that made it.

### Part 09 - P&L attribution

(1) The risk-free rate has no mutation path anywhere in this codebase (see Open issues), so dr and the rho bucket are always zero, matching the prompt's own words ("zero while the rate is constant"). (2) A settling position's vol is zeroed by `portfolio::value_position` once it has no time left, so diffing it against a real previous vol would invent a vol crash that never happened; dσ is forced to zero for a position that has just expired, which leaves the option's whole time-value collapse in the residual — where the prompt says it belongs, since the residual is expected to grow near expiry. (3) `PnlAttributor` rebuilds its tracked-position map from scratch every tick from that tick's `Active` rows, so an expired, errored or removed position simply stops being updated rather than being explicitly evicted; its accumulated `by_position`/`by_underlying`/`portfolio` entries are never deleted, only stop growing, which is what "keeps what it contributed so far today" means in practice. (4) The engine integration test seeds the attributor with the session's opening valuation via one hand-built zero-length `ClockStep`, so the first real tick has something to diff against instead of being treated as a fresh add.
- Open issues: one added above (`MarketState::rate` has no mutation path, so `rho` is always zero).

### Part 13 - Local storage and session recording

- Built: `crates/engine/src/recorder.rs`, a session recorder task. The tick loop hands every record (a `HistoryPoint`, a `SessionEvent`, a session-close `RiskSnapshot`, a daily P&L row, or the book's active positions) to the recorder over a bounded `mpsc` channel (capacity 10,000) with `try_send`; a full channel counts the record as dropped (`AtomicU64`, surfaced in `meta.json` and `/api/health`) rather than the tick loop ever waiting on it — the same back-pressure rule `server::ws`'s `watch`/`broadcast` channels already use for live clients. `SessionMeta` (start, end, seed, speed, git commit, dropped count) is written at start with `end: None` and rewritten at shutdown; a session cut short by a crash is simply one whose `end` stays `None`. `history.jsonl`/`events.jsonl` are batched and flushed at least once a second and once more at shutdown; `closes/<date>.json`, `daily-pnl.csv` rows and `portfolios/current.json` are written immediately, since they are rare. `crates/storage/src/jsonl.rs` gained a reader that skips a truncated last line with a `tracing::warn!` and treats a broken earlier line as a hard error. The git commit hash is captured at build time by `crates/engine/build.rs` (falls back to `RRM_GIT_COMMIT`, then `"unknown"`; watches both `.git/HEAD` and the ref it points at, so a new commit on the same branch triggers a rebuild).
- Built: portfolio persistence. `crates/portfolio/src/spec.rs` gained `write_csv`/`to_csv_bytes`, the Part 5 CSV writer that was still missing — absolute strikes and expiry dates, so a saved version loads back exactly. `Engine::active_positions`/`active_specs` filter out settled positions before every `current.json` rewrite and before a saved version, so a restart can never re-settle (and double-pay) the same option. `config/storage.toml`'s `start_portfolio` (`"last"`, `"sample"`, or a version file name) resolves the starting book in `main.rs`; `"last"` reads `current.json` when it exists and falls back to the sample CSV otherwise. Every session's starting book is saved automatically as `<ts>-session-start.csv`. `EngineCommand::LoadPortfolio` replaces the book, records an event, and rebases `PnlAttributor` against the freshly loaded book's opening valuation, so the swap itself produces no false P&L. Saving and loading a version's CSV file is done in the server's own route handlers (`crates/server/src/storage_routes.rs`'s `save_version`/`load_version`), not through an engine command that touches disk — the engine only ever exchanges already-parsed `PositionSpec`s over its command channel, keeping every file read or write on this crate's boundary out of the tick-loop task.
- Built: size monitoring and the storage API. `config/storage.toml`'s `max_bytes` (20 GiB default) and `warn_fraction` (0.8); `main.rs`'s `monitor_storage_usage` task measures `storage::usage_by_folder` every minute, logs a warning and sets an `AtomicBool` once usage crosses the threshold — the app never deletes anything on its own. `crates/server/src/storage_routes.rs`: `GET /api/storage`, `GET /api/sessions` (id, start, end, simulated days, size, git commit, total P&L), `GET /api/sessions/{id}`, `GET /api/sessions/{id}/history` (downsamples server-side above `max_points`, keeping each bucket's minimum and maximum so spikes survive), `GET /api/sessions/{id}/events?type=`, `GET/POST /api/portfolio/versions`, `GET /api/portfolio/versions/{file}`, `POST /api/portfolio/versions/{file}/load`, `GET /api/market-data/archive`. Every id and file name is validated against a strict pattern (`crates/server/src/validate.rs`) before it ever reaches the filesystem, so `..`, an encoded slash or an absolute segment gets a 400, not a path outside the storage root. `Makefile`'s `storage-usage` target and `crates/storage/examples/storage_usage.rs` print usage by top-level folder and a total against the real storage root; `crates/engine/build.rs` also gained a fix so a new commit on the same branch (not just a branch switch) triggers a rebuild of the embedded git hash.
- Review changes made after the four commits above landed, folded into this same part: settled positions are excluded from `current.json` and saved versions (see above); portfolio version files are read and written by the server's route handlers rather than by an engine command; the `"last"` start portfolio converts positions back to specs via `portfolio::to_spec` rather than re-deriving them by hand.

New coverage includes: a short engine run with a fixed seed recorded into a temp dir, whose history, events, daily P&L and closes all parse back with one history line per tick; a full recorder channel dropping records without the sender waiting, with the dropped count checked exactly (`crates/engine/src/engine.rs`'s `send_pending_records` unit test, added in this part's finishing pass); a shutdown that drains the channel and writes the end time; a truncated last JSONL line skipped with a warning and a broken earlier line treated as a hard error; a portfolio round trip (save a version, change the book, load the version, positions match exactly) and a restart with `"last"` restoring `current.json`; downsampling that returns at most `max_points` and keeps the minimum and maximum of each bucket; path-traversal, encoded-slash and absolute-segment requests all rejected with 400; no test touches the real storage folder, all use `tempfile`.
- Choices the prompt left open. (1) The recorder is the only place in `engine` that performs file I/O — not `Engine::new`, not `Engine::apply`, not `Engine::tick` — so a slow disk can only ever cost a dropped record, never a delayed tick. (2) A settled position's exclusion from the persisted book happens once, in `Engine::active_positions`, and both `current.json` and a saved version read through it, rather than each of the two write paths re-implementing the same filter. ### Part 18 - Value at Risk

- Built: `pricing::normal::inv_cdf` (`crates/pricing/src/normal.rs`), Wichura's AS241 rational-approximation quantile function (three regimes, coefficients in a private `as241` submodule), infallible (`±∞` outside `(0, 1)`, not a panic). New `crates/risk/src/var/` module: `VarMethod` (`DeltaNormal`/`DeltaGammaMc`/`Historical`), `VarMethodReport` (VaR95/VaR99/ES97.5, scenario count, historical window, compute time) and `VarReport` (all three methods plus `headline()`, `total_compute_micros`, `freshly_computed`, `recompute_every_ticks`), and the stateful `VarCalculator` that `Engine` now owns for the session. Delta-normal is a closed-form `sd = sqrt(deltaᵀΣdelta)` double loop (no `nalgebra`). Delta-gamma Monte Carlo draws 10,000 common-random-number scenarios (`ChaCha8Rng` from a fixed constant seed, cached and regenerated only when the active symbol set changes) through a hand-rolled Cholesky-with-shrinkage (`crates/risk/src/var/cholesky.rs`, a deliberate duplicate of `marketdata::simulator`'s algorithm — `risk` cannot depend on `marketdata`) and a `select_nth_unstable_by`-then-partial-sort instead of a full 10,000-element sort every tick. Historical simulation shocks each calibrated symbol's spot by `exp(historical log return)` (vol unchanged, sticky strike) and reprices the whole book with `portfolio::value_all`, measuring each scenario's P&L against an **unshocked** revaluation of the same book (not `summary.totals.market_value`), so a zero-return scenario gives exactly zero P&L. `interpolated_quantile`/`tail_mean_at_or_beyond` implement the linear-interpolation-between-order-statistics and at-or-beyond-threshold-mean definitions used by all three simulation paths. The 1 ms compute budget is adaptive: every tick computes until `VarCalculator` has timed 20 computed ticks (cache-rebuild time excluded from the timing, so the first tick's one-off 10,000×n draw never trips it), then decides once, from the *median* of those 20 samples, whether to throttle to every `N`th tick (`N = ceil(median / 1000 µs)`, clamped to `2..=10`) for the rest of the session — `recompute_every_ticks` is carried on `VarReport` so the UI and notes can say so.
